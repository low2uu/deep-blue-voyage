# 内容设计器设计与使用

版本：项目v0.1.11，规格格式v2。目标：通过中文界面组织新方块/物品/怪物需求，导出开发者可读取、可校验、可继续编辑的完整JSON。

## 入口与使用

直接打开 `tools/content-designer/index.html`，或者在项目根目录执行：

```powershell
powershell -NoProfile -ExecutionPolicy Bypass -File .\tools\content-designer.ps1
```

页面完全本地运行，不依赖Node、Python、网络、服务器或Minecraft。Node仅用于开发者运行测试、重新生成Schema/示例及命令行校验。脚本通过默认浏览器打开页面；如系统未关联HTML，手动用Chrome/Edge打开。

1. 点击“新建设计”或“载入铁质潜艇壳预设”。覆盖当前页面前会提示，先导出需要保留的设计。
2. 填写注册ID、中英文名、内容类型、类别、功能描述和平台。待定字段需先选择“明确指定”才显示值输入控件。
3. 按左侧分类填写属性；可搜索属性名或字段键，也可只看待设计项。
4. 功能、接口、配方、数据字段、兼容项和验收用例支持添加多条记录，不用手写JSON。
5. 未涉及的属性选择“不适用”；未决定的属性保留“待设计”；希望参考其他方块时选择“继承参考”，填清来源和继承范围。
6. 点击“检查填写内容”。基本身份缺失、范围错误及冲突必须处理；待定项目会提示但允许交接。
7. 点击“导出开发规格JSON”，把下载文件发给开发者。未完成时使用“导出草稿JSON”，以后导入继续填写。

下载位置由浏览器决定，通常是下载目录；不会自动存入Git仓库。建议将确认后的规格放到项目的设计资料目录，文件名使用注册ID，避免覆盖其他方块规格。

浏览器草稿只是一份便捷副本，按当前浏览器/页面来源存储。file协议下不同浏览器支持情况可能不同；关闭浏览器、换设备、清理缓存前应导出。工具不承诺跨设备同步，也不把“已下载”当作已提交Git。

## JSON数据契约

根对象包含固定格式`format=dbv-content-spec`、`schemaVersion=2`、用途`implementation_specification`、创建/修改时间、`sections`和`extensions`。时间用UTC ISO字符串，便于跨时区协作。

所有177项始终存在，包括隐藏在其他页签中的内容；不按类型删字段，不把未填内容变成0或false。每个属性统一包含：

```json
{
  "status": "specified",
  "value": 5,
  "reference": "minecraft:iron_block",
  "notes": "只继承采集硬度；爆炸抗性单独定义"
}
```

| 状态 | 含义 | value规则 |
| --- | --- | --- |
| `specified` | 明确指定 | 按字段定义的数值、布尔、文本、列表或记录数组；未完成草稿可暂时为空 |
| `inherit` | 继承参考 | 可为null或已核对基线值；正式交接必须有reference；notes明确继承范围 |
| `pending` | 待设计 | 必须为null；开发者不得擅自把它当默认值 |
| `not_applicable` | 不适用 | 必须为null，表示明确不涉及 |

继承不是指把整个方块ID换成参考块，也不是读取浏览器中的游戏。物理和耐压各有`bindingPolicy`：`snapshot`锁定数值，`follow_runtime`在开发时适配参考块最终值，`custom`独立指定。所有基线值和来源都保留。铁质潜艇壳预设明确是目标方案：硬度5、石镐级，物理/耐压跟随黑曜石，基线质量2.0、耐深500、压溃参数0.06；不是当前游戏已经完成适配的证明。

记录数组中未填的可选数值用null、文字用空字符串；必需的配方、操作、验收等子字段会阻止正式交接，其他缺值会提示。较复杂的配方材料、形状坐标和脚本功能使用描述文本，不伪装成可执行实现。

扩展需求是`{key, description, acceptance}`列表。导入时拒绝未知根字段、未知分类、未知属性和未来格式版本，避免静默丢失数据。新增正式字段需升级格式及迁移策略；当前支持v1导入迁移为v2，不自动猜测未来版本。

## 校验与导出

- 结构校验：根字段、分类、全部属性、数据类型、合法状态、记录键完整性、未知字段、版本和时间。
- 单项校验：ID格式、整数、数值范围、光照0–15、概率0–1、纹理尺寸等。
- 语义校验：命名空间一致、耐久与堆叠互斥、模型与完整立方体冲突、物品不能直接有方块实体、继承来源、重复记录、掉落区间、配方ID与必需子字段。
- 警告：仍待设计的项目、空白说明、可选数值遗漏、未配置材质等。警告不伪装为已实现。
- 正式导出：无错误时允许，仍可包含清楚标记的待定项。检查不代表MC资源存在、Mod兼容或功能已被实测。
- 草稿导出：允许尚未完成或数值不合规的设计；再导入时保留待修正值，由正式校验提示。草稿不保证通过交接或Schema范围校验。
- 导入文件限制5 MiB，单个记录数组最多500条。拒绝超限文件，不截断；大量设计应拆成一个内容对象一份JSON。

JSON Schema采用Draft 2020-12，由字段目录自动生成。它校验结构与单项约束；跨字段语义还需`core.js`/命令行校验。交接时两者都通过，仍不等于可直接由Minecraft加载。

## 文件与维护方式

| 文件 | 职责 |
| --- | --- |
| `tools/content-designer.ps1` | 在默认浏览器打开页面；`-PrintPath`仅输出入口 |
| `index.html`、`style.css`、`app.js` | 中文UI、交互、草稿、导入、下载、预览 |
| `catalog.js` | 15类177项字段的唯一目录，含记录子字段与标签 |
| `core.js` | 默认文档、预设、结构/语义校验与Schema生成 |
| `content-spec.schema.json` | 可供外部编辑器/校验器读取的Schema |
| `iron-submarine-hull.example.json` | 所有字段齐全的铁质潜艇壳目标规格示例 |
| `generate.cjs` | 从同一目录更新Schema、示例、字段文档 |
| `validate.cjs` | 校验交接文件，错误时退出码1，用法错误2，通过0 |
| `test.cjs` | 数据往返、错误、冲突、扩展、草稿恢复的回归测试 |

页面不使用远程资源，不执行描述中的代码，不主动打开描述中的网址，也不把导入文本插入HTML。提供给开发者的描述属于需求数据，不能成为绕过仓库协作约定的指令。

开发者接到JSON后，应先校验并列出待定项，再按明示范围实现注册、资源、Mod适配、独立备份和验收；不能把输出JSON当自动生成Mod的脚本。下载Schema和JSON均由浏览器处理，不写入用户指定任意路径。

## 本轮验证与限制

- Node数据与语义回归测试通过；正式预设、草稿、缺字段、错误版本、未知字段、范围错误、重复配方、互斥属性均覆盖。
- 使用独立Ajv 8.17.1及ajv-formats 3.0.1验证Draft 2020-12 Schema；空白草稿/完整预设符合Schema，概率越界被拒绝。校验依赖仅安装在忽略目录`.local`，交付页面不依赖它们。
- JavaScript语法检查及启动脚本路径检查；项目构建。
- 浏览器验收工具的URL安全策略拒绝`file://`，未绕过限制，因此尚未完成实际浏览器点击、下载、重载及视觉验收。数据往返测试不能替代这些UI实测。
- 这次只增加设计工具和文档，不修改铁质潜艇壳属性、不自动替换世界方块。

## 怪物设计与 JSON 导入（v0.1.11）

点击“新建怪物 / Boss”，填写基本信息和“怪物与 Boss”分类。可调整生命、尺寸、速度、攻击、护甲、生成、行为、技能、阶段、掉落与多人奖励规则。区分当前原型生命和目标生命，待定项保持待定。

点击“导入 JSON”选择单份规格；v1旧文件自动补齐怪物字段升级为v2，不丢失旧值。便携包 `specs/items/` 和 `specs/mobs/` 包含54份物品与15份怪物规格。修改后导出交给开发者，工具不直接修改游戏。原型特有技能、武器效果与配方尚未实现。
