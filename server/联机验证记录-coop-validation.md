## 本次修复的服务端崩溃

Deep Seas 3.3.0 的材质探测通过 `Class.getMethod` 查询可选的伪装方块接口。Dashpanels 的 `CeilingPanelBlockEntity` 含仅客户端可用的方法签名，反射会触发 `PoseStack` 的独立服务端加载错误。

测试实际触发了这个异常，新增兼容 Mixin 将该可选接口视为不可用，继续原 Mod 的 NBT/原方块材质回退。两种可选接口均记录一次警告并缓存结果，随后输出：

```text
DBV_SERVER_MATERIAL_CHECK_OK blockEntities=317
```

没有关闭耐压检查，没有修改浮力、升降速度、推进和材料数值。测试用 KubeJS 检查脚本已经移除，不随服务器包交付；未给游戏增加调试入口。

## 已知日志与未验证部分

- Power Grid 在本机没有加载原生加速库，使用其可用的 Java 路径；本次启动不因此失败，不代表复杂电网性能已验收。
- 原模组仍有 `wdutils` 缺失访问转换文件、柴油模组单个掉落表引用等日志。
- 历史地图有 `create_abyss:abyss` 维度引用，当前生产版内嵌的 Create Abyss 禁用内容，首次读取有维度解码日志；主世界、下界、末地成功加载。本次不添加或启用 Abyss。
- 航空学工具枪在主艇蓝图采集时会输出部分方块实体缺少依赖列表的警告；实际输出了包含 317 个方块实体的蓝图。复杂机械的完整灾难恢复仍需专门测试。
- 无玩家时建设模式不常驻加载船坞，状态可能是“未加载”；这不等于主艇损毁。测试通过临时加载船坞区块验证，结束后解除。
- 尚未完成两个正版账号跨网进入、驾驶时的网络同步、双方同时改装/操作存储、长时间运行和完整备份恢复后的实机驾驶。不要将本次开服验证当作这些功能全部验收。

双方首次联机建议依次确认：同一版本进入 → 在初始岛见到彼此 → 控制台显示同一主艇 → 存取物品 → 航行/停泊 → 停服重启后物品与主艇状态保留。开始正式建设前再留一份完整备份。
