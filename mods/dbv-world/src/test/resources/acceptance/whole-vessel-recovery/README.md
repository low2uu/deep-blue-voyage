# 整艇恢复整合验收

该目录是独立的验收 Mod 源码，不加入正式整合包。探针会创建测试潜艇、修改设备、删除物理船体并中断恢复事务；只能用于脚本创建的 `.local/acceptance/whole-vessel-recovery` 世界。

准备（构建、编译并复制依赖，但不启动游戏）：

```powershell
powershell -NoProfile -ExecutionPolicy Bypass -File .\tools\test-whole-vessel-recovery.ps1 prepare -Offline
```

运行四次无界面服务端验收，服务端每阶段自动写报告并退出：

```powershell
powershell -NoProfile -ExecutionPolicy Bypass -File .\tools\test-whole-vessel-recovery.ps1 run
```

- `recover`：默认世界5蓝图，等待原生资格登记；添加真实木桶、电解器、氧气释放器和柴油储罐作为可重复样本；保存组件物品、耐久、水、氧气、FE和柴油；删除整艘船后恢复并核对。
- `restart`：重启后核对永久身份、物品及设备内容，再删除船体并在新船导入、身份尚未提交时停止服务器。
- `resume`：重启处理未提交事务，再执行整艇恢复并核对。
- `splitrollback`：在已恢复潜艇的现有包围盒内找六面空气的位置，放入带有17颗标记钻石的悬空木桶，同一刻建立完整检查点、删除原艇并恢复；验证原生物理确实拆出子船体、内容核对拒绝该次导入并完成回滚。检查永久身份和代次未变、全部候选及分裂子船体从内存和原生磁盘索引消失、没有掉落物副本、其他独立船体集合不变、恢复检查点哈希不变。

探针保留原艇的全部设备和机械轴承运动结构，样本设备只用于明确断言。样本采用独立流体回路，通过铁支架连接原有艇壳；支架从暴露的实体壳方块向上连接外侧横梁，不覆盖原有设备。放置后等待至少60刻，确认只有原主船体、系泊有效且速度稳定再生成检查点，避免悬空样本被原生物理拆成独立碎片。为避免岸供改变样本数值，探针在测试世界里通过反射停止岸供、禁用样本电解器；不修改正式代码或机器默认值。

最后的分裂回滚是有意制造的不完整船体，用于重现恢复失败时碎片与货物残留的回归场景。报告必须从本次归档事务中确认存在分裂后新增的候选ID；如果根本未发生分裂，不能算通过。该阶段结束后，测试世界没有主艇实体，完整恢复点仍保留，这是负向验收的预期结果。

脚本只从现有服务端读取加载器 `libraries` 和已有 EULA 接受状态，不复制或修改正式世界。若缺少已装加载器，则使用经过 SHA-256 核验的缓存安装器在验收目录中安装。网络监听限定为 `127.0.0.1:25667`；没有客户端窗口。

`probe/probe-classpath.txt` 记录编译 classpath；`probe/dbv-recovery-probe.jar` 是独立探针。`manifest.json` 固定此次验收的 Mod 哈希；`reports/` 保存预期数据和四份阶段报告，`splitrollback-expected.json` 额外记录分裂夹具坐标与初始候选清单。已有失败目录不自动清空或重复覆盖，修复后重新执行 `prepare` 创建新一轮证据。

准备成功不等于实机验收通过；只有四份报告均为 `passed: true` 才算完成此项验收。该探针验证服务端实体、设备和持久化，不证明客户端按钮视觉、渲染或多人操作界面已经验收。
