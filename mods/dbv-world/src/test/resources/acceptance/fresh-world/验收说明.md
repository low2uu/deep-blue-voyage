# 新建世界生成回归验收

这是开发客户端的验收夹具，不进入正式 Mod，也不作为游戏功能加载。使用与正式环境相同的 Mod 清单；通过临时 Gradle init 把此目录加入 main Java 来源，并将 client.gameDirectory 指向空的临时客户端目录。将 client.js/server.js 分别复制到该目录的 kubejs/client_scripts 与 kubejs/server_scripts。不要在正式游玩目录执行。

必须确认 saves/DBV-Fresh-Seed 不存在，不能复制已有 level.dat、region 或 dbv 数据。客户端脚本会经 Minecraft 的 createFreshLevel 流程，使用注册的 dbv_world:starter_island 世界预设与种子 1357924680 创建真正的新世界。

验收包括三个主线核心与边界、24 岛中心及岸线邻块，检查种子不同、生成器正确、矿脉不混矿、七个矿种（含机械动力锌）、起始岛建设审计。输出 kubejs/fresh-done.json；done 不等于通过，必须检查 passed 与 error。验收后再次打开同一新世界检查保存持久性，最后清理临时世界，并用正常 build 构建正式 JAR，检查不包含 dbv/acceptance 类。

现有 VoyageLayoutTest 还覆盖 1000 个种子的布点数量、边界、互不重叠、缓存淘汰后种子稳定性以及矿脉埋深。布局测试与真实新建世界验证相互补充，不能用复制既有合格存档代替后者。

保存重进时替换为 reload-client.js 与 reload-server.js（不要同时保留 create 脚本），移走第一次 fresh-done.json，再运行客户端。重进脚本只对这个临时验收世界处理首次实验性预设提示，不清除缓存、不修补地形；验证海面、最低高度、边界以及 27 个地点的保存结果。
