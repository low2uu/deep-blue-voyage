更新于 2026-10-14。当前目标是把起始岛的基础生产和施工保障做起来。保留原有 96×96 工厂及扩建带，先使用其中 48×48 格；动力、树场、仓储各先启用一小块。此前提出的 160×104 六车间大园区不采用。

本方案只选择现阶段需要的蓝图，不要求把蓝图站的所有机器、所有已批准附属 Mod 的产线都建出来。完整检索结果保存在[机器蓝图库](机器蓝图库-machine-blueprint-catalog.md)，便于下次选型；[结构化清单](machine-blueprint-catalog.json)同时记录具体下载项、尺寸和验证状态。

当前核心四区（加工、动力、树场、仓储）启用地块合计 **5376格²**；加普通田和厨房是 **6656格²**。这是分散地块面积之和，不含地块间道路、船坞和未施工预留地。没有理由因一台3×5×3锅炉就修满64×40动力房，也不能因树场蓝图只有11×6×11就把树冠空间封住。

基础厂48×48的摆放草案：工作站位于X=80～104、Z=-64～-40；刷铁机工位X=108～124、Z=-64～-48；安山合金工位X=108～124、Z=-44～-28。三个工位之间留4格通道，南侧留接线与小缓存。工位内部至少留2格检修空间；若实际变体超出预算，优先在原96×96内调整，不压缩检修通道。

蓝图尺寸、工位预算、整个厂房面积是三个不同数字。厂区主通路按6～8格预留，工位间通路4格；较长输送带和流体主管另走公共管线带。仓库到工厂先完成一条可靠收发路线，再增加包裹网络，避免所有机器都被同一条未经验证的物流链卡住。

## 兼容性与实施边界

CMS-1413作者明确列出Create 6.0.10；CMS-967是1.21.1/6.0.8并有站点用户反馈；CMS-840分别提供1.21与1.20.1主体。它们的证据强度不同，实装时仍需按目标6.0.10运行测试。旧版本不会仅因标签被丢弃：例如[CMS-113](https://www.creativemechanicserver.com/detail/113/)作者明确说结构可跨版本，但过滤与移动结构状态需要调整。

采用Create现有机械、蓝图和物流能力，不为这些基础产线另写Java实现。dbv-world继续负责起始岛与建设阶段规则；目前也不需要为复制其他整合包的专用产线添加KubeJS配方。当前没有自然矿物和刷怪供应，施工原料与未来生存资源必须分开记录。

所有生产模块按需求启停，满库存关机，不新增常加载器、不预生成远海。停掉传动不保证所有容器和Mod逻辑零耗时，最终以实际游戏耗时为准。锅炉按同时运转工位统计负载，预留约25%设计余量；网页“内置”应力只作字段原文，逐台检查真正的动力来源。

## 下次实装的完成条件

先备份现有施工存档，在同一个正式开发环境逐台部署：核对下载文件 → 读取尺寸与缺失方块 → 试装和配置 → 接电力/应力及物料 → 运行与停机测试 → 保存重载 → 导出经过修改的复用蓝图及说明。只对实际改变过的模块重复验证。

一台机器只有在目标版本下能正常启动、产出正确物品、缺料后恢复、满箱停止、重载后继续工作且不越出预留运行范围，才在蓝图库标记“项目实测通过”。这次完成的是选型和可复用目录，后续无需重查同功能候选及版本文件，但仍须做这一步验收。
