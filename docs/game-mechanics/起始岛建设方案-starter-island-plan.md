> 此文记录最初的空岛环境与用地草案。2026-10-14的建筑和自然地形已在新存档完成，当前成果、出生点及工位净空请看[起始岛建筑与环境初版](起始岛建筑与环境初版-starter-island-built-v1.md)。原空岛存档保留，本文的Y=68大平台与“不自动建房”描述不代表新建成版。

更新于 2026-10-14。保留此前整体地图与科技路线方案，当前只完成起始岛施工环境。岛外保留简单海面，按玩家视距生成区块，不预生成远海，不加入海底结构、装饰、矿物或复杂群系。建设阶段的低负载配置可关闭，不代表最终生存玩法。

## 当前工程与临时设置

统一使用 `deep-blue-voyage.code-workspace`、`mods/dbv-world` 源码和 `runtime/client`。启动命令为 `powershell -NoProfile -ExecutionPolicy Bypass -File tools/dev.ps1 run`。

建设开关集中在 `config/development-session.json`：

| 设置 | 当前值 | 作用 |
| --- | --- | --- |
| constructionMode | true | 临时建设模式；水下地表使用基岩，进入起始岛世界后关闭自然刷怪、巡逻、商人、幻翼、监守者生成及袭击 |
| renderDistance | 6 | 降低客户端视距；大型岛屿不能一次看全，可移动观察 |
| simulationDistance | 5 | 降低实体与区块模拟范围 |
| maxFps | 30 | 减少客户端持续渲染负载 |

进入该预设的存档后，出生区常驻半径设为 0。原规则保存在该存档内的 `dbv-construction-rules.properties`；将 constructionMode 改为 false、重启客户端并进入同一存档后恢复原规则。视距等选项也会在下次启动时恢复此前值。首次启动前没有 options.txt 时，关闭模式后删除所管理的键，由游戏使用默认值。不要在客户端运行时切换配置或同时启动两个客户端。

未通过项目启动脚本而直接使用 Gradle 时，建设模式默认关闭；可用 `-PdbvConstruction=true` 明确开启。构建出的 Mod JAR 默认不会给普通玩家启用建设模式。

游戏规则主要约束原版生成机制，不能保证阻止其他 Mod 自行创建实体。刷怪蛋、命令和后续手动放置的 NPC 不会被一律删除；首批 Mod 的自定义生成行为仍需运行验证。设置在服务器启动后应用，不用于把现有世界中的实体清空。

## 空岛地形

岛屿中心位于原点附近，椭圆尺度约 512 × 384 格；陆地实际边缘略小并有轻微起伏。建设平台 Y=68，初始出生点约 (-80, 69, -40)，水面高度为 Y=63，远处海底 Y=-45。南侧船坞航道位于 X=0～128、Z≥112，海床不高于 Y=12。

当前海底为简单基岩表层，下方仍有基础填充层，没有矿脉和洞穴。岛上保留草地与泥土，不自动建房、不种树、不放 NPC。当前也不具备正式生存资源分布。

规则可以恢复，已经写入存档的基岩海底不会随开关恢复。正式海洋生成器完成后，先备份并确定保留范围，再迁移岛屿或有选择地重建外围区块；不会自动删除已有建筑。当前不承诺直接切换开关就能无缝接上正式海洋。

## Mod 与自研分工

| 功能 | 当前安排 |
| --- | --- |
| 起始岛、海面、出生位置 | 自研 dbv-world，当前使用简单固定形状生成器 |
| 临时建设开关与原规则恢复 | 自研启动配置与 ConstructionMode，独立于出生点规则 |
| 工厂机械、潜艇基础能力 | 先加载已确认的 Create、Sable、Create Aeronautics、Create Deep Seas、Power Grid 及 Architectury；仍需组合运行验收 |
| 初始建筑 | 后续用可版本管理的结构或蓝图部署，并记录部署状态，避免覆盖玩家施工 |
| 任务、手册、对话和商店 | 之后从已批准的清单中选用；本阶段不为此增加新 Mod，也不预先承诺已有完整 NPC 系统 |
| 正式海洋、Boss、压力锁、速度锁、体积锁和 AI | 保留原设计，暂不实现，也不为这些区域预生成区块 |

## 验收顺序

先构建与启动，再验证世界预设、地形和临时规则。随后确认设施分区，再建建筑。每一阶段区分源码已实现、自动检查通过和实际游戏验证，不能将编译成功视为世界创建成功。
