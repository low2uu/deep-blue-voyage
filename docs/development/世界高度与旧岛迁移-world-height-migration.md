# 世界高度与旧岛迁移

2026-10-16：用户确认现在修改世界生成，并处理旧岛迁移。

> 后续同日更新：本文保留v3高度迁移记录；当前入口已改为v4淹没世界，外海生成及旧v3归档见[淹没世界生成与开发边界](淹没世界生成与开发边界-flooded-world-generation.md)。

## 高度基准

| 项目 | 当前设置 |
| --- | --- |
| 海面基准 | Y=128，最上层水方块Y=127 |
| 世界底部 | Y=-256 |
| 最高方块 | Y=319，排他上界320 |
| 总高度 | 576格 |
| 原岛与设施迁移 | 所有世界坐标整体增加65格，X/Z不变 |
| 主要建筑平台、出生站立高度 | Y=133、134 |
| 临时建设外海海床 | Y=20，保持原来的相对水深 |

维度类型为`dbv_world:ocean`，只由起始岛世界预设使用；不覆盖其他普通主世界的维度定义。下限扩大后，旧世界底部以下用石头补齐，最底层为基岩。现在仍是低负担建设地形，未生成三个主线区域，亦未把海底直接挖到世界下限。

深度统一按`128－世界Y`换算。例如260格深处为Y=-132；世界高度已可容纳该深度，但未来仍须实际制作海床、航道和内容。

## 源码与迁移边界

- `WorldHeights`集中定义高度；地形、建筑、船坞装配与改装区域一并迁移。
- `tools/migrate-world-height.py`离线复制存档，先建立ZIP备份，不覆盖原档或已有目的目录；需要Python、NumPy、nbtlib。
- 区块方块重新按16格分节编码，调整高度图、方块实体、计划刻、POI、实体、玩家与出生点；旧底部基岩改为石头，新底部放置基岩。光照标记失效后交由游戏重新计算。
- Sable移动船体世界姿态和世界边界，同时把相对世界底部的存储区段索引增加12、重新编码高度图。船体虚拟坐标、设备局部坐标、库存、船体登记和业务备份保留。遗漏区段索引转换会使方块与设备错位，已增加针对这一问题的回归测试。整体抬高不改变相对海面的深度。
- Minecraft 1.21.1的`Level.getSeaLevel()`仍固定返回63；通过限定`dbv_world:ocean`维度类型的Mixin使该查询在客户端和服务端均返回128。
- 这是针对已检查的建设存档的一次迁移工具，不是任意整合包的通用迁移器。发现未适配的固定方块实体、生成结构、外部区块存储、活动改装或高处方块将被截断时会拒绝继续。
- 必须关闭游戏后运行；不应在运行中的存档上执行。脚本末尾核对原目录内容哈希，确认源存档未变。

## 存档与回退

正式迁移档已发布为`runtime/client/saves/DBV-Island-v3`，显示名`Deep Blue Voyage - Sea 128`。通过标准`tools/dev.ps1 run`开发环境进入该存档。旧v2原目录已移入下述归档目录的`DBV-Island-v2-original`，避免误开旧高度地图。

完整旧档备份位于`runtime/world-archives/height-20261016/DBV-Island-v2-final-source.zip`，同目录保留迁移前`dbv-world-before-height.jar`。回退需同时恢复旧世界生成代码与旧档；不能把新生成代码直接用于旧高度存档，否则新旧区块高度不一致。

`runtime`、`.local`均不提交Git；源码、迁移工具、说明和验收摘要进入仓库。不能只拉取Git仓库就获得本机迁移存档。

## 验证记录

- Java项目构建通过。
- Python迁移测试覆盖长整型位打包、跨区段平移、高度图、方块实体、普通玩家与Sable虚拟坐标区别。
- 离线迁移处理2925个区块、4个标牌、1艘Sable潜艇；原存档哈希保持不变。
- 实际载入及保存后重开均通过：主世界下限-256、上界320、海面128；未生成过的(2000,2000)海域检查底层基岩、127层水及128层空气。
- 每次验收通过102080项方块检查：5处机器预留工位、128×128船坞水域和上方净空、出海口、干燥安全出生点。
- 两次验收均为`controller=true, oxygen=true, sealed=true, pending=false`。船体虚拟旋转中心Y仍为132.855，迁移后世界中心Y约107.76，符合原Y约42.76加65；不进行航速测试。
- 结果与验收脚本保存在`outputs/world-height-20261016`。脚本会按需加载少量海域并保存副本，不搭建或改装设备。临时副本中的自动验收脚本已禁用，正式运行入口仍为`tools/dev.ps1 run`。
