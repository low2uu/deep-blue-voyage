# 潜艇扫描上限

2026-10-19：当前方块改装、连接扩建扫描、物理主艇结构/存储扫描及改装恢复校验，统一使用 `RefitService.MAX_SCAN_VOLUME = 1_048_576`，原值为 32,768，提高32倍。

这个数是轴对齐包围盒的长×高×宽，**包含空气**，不是实心方块数，也不是扫描半径。例如128×64×128格恰好达到上限。超限时拒绝扫描，不截断船体或覆盖成不完整备份。

改装事务档案的NBT读取核算预算从16 MiB提高到512 MiB，写入前使用同一预算进行解码验证，避免写入成功但重启无法读取。此预算是NBT读取器的内存核算额度，不是压缩文件大小或Java进程总内存。独立主艇业务档案仍使用JSON；此处调整的是已有改装事务日志。

保留船坞空间、连接岸边检查、区块加载完整性、上游物理引擎与密闭扫描限制。旧版活动改装记录的4096格限制保持原样，直到旧事务完成。单容器4096槽及存储面板槽位限制不属于船体空间扫描，本次不调整。

扫描与转换目前仍在服务器线程执行。1048576是本次扩大后的工程限额，不是已证明的最大安全船体规模；密集设备、完整快照和原生运动结构会增加耗时与内存。超大型船需要后续分批扫描/转换及压力测试，不应直接取消所有边界或设为整数最大值。已有船坞的形状与尺寸不会随本次限额调整而扩大。

验证：Gradle构建和现有测试；新增超过旧16 MiB预算的事务快照创建、替换及重读回归测试。尚未进行百万格实机压力测试。
