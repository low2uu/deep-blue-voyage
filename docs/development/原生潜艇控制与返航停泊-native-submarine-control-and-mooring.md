# 原生潜艇控制与返航停泊

适用：Minecraft 1.21.1 / NeoForge 21.1.259，Deep Seas 3.3.0、Sable 2.0.6、Create 6.0.10、Diesel Generators 1.3.15。

## 本次改变

撤回 `BallastDepthControl` 和对主艇的自写速度反馈，恢复 Deep Seas 原生 `steer`、`trim`、压载舱和浮筒物理。仅保留已经约定的控制器中心测深、世界坐标换算及未知水面保护，不缩小碰撞箱，不用额外冲量强行维持目标深度。

初始艇改为四角4个独立压载舱、船底16个原生浮筒。压载舱每个8桶，初装半舱水。整艇质量以运行面板为准，未经扩建的模板约2832。默认目标1米、原生中速档、关闭海底跟随；这里的中速档仍受整包降低后的升降速度上限约束。

`config/submarine-balance.json` 设定原生参数：压载单舱升力9000、升降速度上限0.2、浮筒升力300。`tools/dev.ps1 run` 同步到客户端配置。这些不是上游默认值，影响整包所有潜艇，不能解释成“任意重量和任何改装都能正常航行”。质量、浮筒数量、泵速及含水量仍需要匹配。

修正两处模板连接：

- 柴油管在前压载管上方采用只连北/上的机壳流体管，防止柴油与压载海水管网自动连通。此前日志确实出现前舱积水、后舱排空；隔离后四角进排水量一致。
- 换向器移到双桨支路，原服务主轴保持同向。舱内原位置的拉杆通过Create原生红石链路控制对应桨，支持独立启停和换向。拉杆底座采用机壳传动轴，避免装配时脱落。链路频率左侧为指南针＋红色染料，右侧为指南针＋蓝色染料，不要随意改成相同频率。

Create储罐为8桶/块，已按实际容量修正预装：柴油左右各两块储罐、各16桶，发动机各1桶启动油；淡水8块储罐64桶，电解器另4桶。初始化必须接受全部预装量，否则拒绝交付，不能将部分填充报告为成功。柴油和淡水真实消耗，停车并不等于停机。

## 驾驶和停泊

1. 关闭舱门、查看中央面板三项合格，检查燃料与水。中央管理面板右上角有中文“驾驶指南”。
2. 点击“出航”，解除固定与岸供。先保持默认1米定深；深度从控制器中心计算，艇底更深。
3. 面朝艇首，左右凹位拉杆是推进离合器。出厂开启拉杆表示离合断开、桨停车；两侧均接通则同向航行。发动机前上方拉杆控制各自换向，两侧均反向可倒车，一侧换向可转向。双桨沿艇身轴线安装，不支持独立横移。
4. 普通右键中央控制器设置深度；潜行右键打开主艇管理。螺旋桨须浸水，目标深度须留出船底净空。
5. 返回初始船坞，断开两侧推进离合器，等待船体稳定。“出航”按钮此时显示为“停泊”；点击后在当前位置固定船体、恢复岸供。再次点击“出航”可继续航行。

停泊暂限建设模式创造管理员，与现有改装/出航权限一致。需要主艇完整载入、没有进行中的改装、玩家靠近、整艇位于主世界船坞边界（X 0～128、Z 112～240、Y 13～100），推进桨停转，Sable线速度不大于1、角速度不大于0.15。按钮不可用时显示具体原因。不会自动返航、传送至旧锚点或替玩家驾驶。

停泊前保存独立JSON业务/船体/容器快照，持久化当前锚点与朝向，建立Sable固定约束。建立失败恢复出航状态，避免把未固定的艇显示成已停泊。已有船坞底层锚点文件仍使用原来的 `dbv/fleet/dock/starter.nbt`；这不是把独立业务和存储备份改回NBT。

## 更新及验收

已有世界不会自动覆盖旧艇。先停泊，再执行 `/dbv refit angler`，检查后 `/dbv refit commit`。替换保留唯一主艇ID，先备份原艇；原容器物品迁移到新箱子和木桶，超容量则拒绝。升级与普通改装均不保证自动沿用旧设备燃料、配置和扩建布局。

最终参数在真实客户端存档副本中测试，稳定阶段最后6次采样覆盖25秒：

| 原生档位 | 动作/目标 | 实测控制器深度 |
| --- | --- | --- |
| 低速 | 从约5.3米上浮至1米 | 0.99～1.02米 |
| 低速 | 从1米下潜至5米 | 4.98～4.99米 |
| 高速 | 从5米下潜至15米 | 14.98～14.99米 |
| 中速 | 从15米返回1米 | 1.03～1.04米 |

全过程样本保存在 `outputs/native-starter-20261015/native-modes-and-restart.log`，统计为 `depth-measurements.json`。其中seq=1～3是浮力400/200的对照失败配置，最终300对应seq=4～7，不应混用。

双桨实测正转96/96、反转-96/-96，前进时Z由153.508减至153.005，倒车回到153.296；单侧反转产生相反方向的偏航变化。反转不影响三项资格。停泊在桨运行时被拒绝；双桨停止后通过真实UI执行“停泊→出航→停泊”，锚点稳定，重进存档仍保持停泊。驾驶指南和实际存储终端已打开并检查截图。最初航向/UI检查使用浮筒400的中间配置；随后调整为300，完成上表三档升降，并在待交付世界中再次验证默认中速出航、前进、倒车、左右换向及UI停泊。最终默认1米实测约1.00米；记录为 `final-delivery.log` / `final-delivery-ui.log`。转向过程中有一次舱室重扫显示pending，随后恢复三项合格，最终停泊验收通过。

`native-full-acceptance.log` 末尾有验收脚本对菜单调用 `getClass()` 的Rhino错误，不是终端打开失败；之后 `native-restart-ui.log` 的实际客户端复测和 `存储终端-storage-terminal.png` 确认终端正常，保存的验收脚本已修正这个诊断调用。源码构建与25项单元测试通过。

范围限本版未扩建初始艇、已测试水域及档位。尚未验收长途续航、负载变化、1～15米之外的深潜、海底自动跟随、整套气闸水下往返。更改船壳、燃料/储物负载或原生配置后需要重新试航，不能据此保证任意改装都不沉底。

正式世界升级保留主艇ID，载体由第4代更新为第5代，最终双桨停车、换向复位、已停泊，玩家位于舱内。旧正式世界完整备份保存在本机 `runtime/world-archives/native-upgrade-20261015/原生控制更新前世界.zip`，不上传玩家恢复档案。
