# 主艇独立数据与舱内面板 / Vessel Data and Cabin Panel

更新：2026-10-14。适用 Minecraft 1.21.1、NeoForge 21.1.259。

## 核心约定

主艇业务数据按永久 `vesselId` 归档。物理载体 UUID 可以在改装时改变，业务数据目录不变。面板是无状态入口，不存放仓库数据，不绑定某一份方块实体 NBT；拆除面板不会删除主艇档案。

按照已确认方案，实际箱子、木桶及其他物品容器是运行中的物品来源，独立 JSON 是观察记录及可恢复快照，不是另一个可以重复取物的虚拟仓库。新增主艇业务模块必须接入同一数据仓库，不另建零散存档，不把权威业务数据挂在控制器或面板 NBT 上。

## 目录与格式

```text
<世界>/dbv/fleet/vessels/<永久 vesselId>/
  state.json                    # schemaVersion、vesselId、modules
  backups/<快照 UUID>.json       # 完整业务快照，含 SHA-256 校验
  automatic/<快照 UUID>.json     # 自动快照，最近20份；不清理手动 backups
  storage-recovery.json         # 仅在存储恢复执行中存在；保留恢复源和恢复前快照 ID
  *.pending                     # 中断写入标记，禁止自动覆盖
```

当前模块：

| 模块 | 内容 | 权威来源 |
| --- | --- | --- |
| `vessel` | 名称、维度、当前物理载体、代次 | 既有唯一主艇登记；这里是便于归档的副本 |
| `storage` | 容器相对位置、方块 ID、槽位数、逐槽物品及组件 | 实际舱内容器；JSON 用于备份恢复 |
| `storageBackup` | 最近一次手动存储备份 ID | 独立 JSON |
| `structure` | 船体方块相对位置、状态及方块实体完整元数据 | 真实物理船体 |
| `automaticBackup` | 最近自动快照 ID、变化指纹 | 独立 JSON |
| `navigation` | 是否已出航、是否禁止自动系泊 | 独立 JSON |

物品使用注册表感知的 `ItemStack.CODEC` 与 `JsonOps` 编解码，可保留名称、附魔、耐久和已注册组件；不是压缩 NBT 文件，也不是把二进制 NBT 转成 Base64。Mod 自定义组件可能有自己的结构，必须在对应 Mod 仍安装时恢复。未知模块在更新其他模块时原样保留，为后续 AI 船长、任务、维修与能源数据扩展留出入口。

文件先写 `.pending` 并强制落盘，再原子替换。备份不可覆盖；读取时校验内容摘要和永久主艇身份。读取损坏、未知版本或未完成写入时拒绝覆盖，不把错误当成空仓库。快照包含整个业务数据根，恢复某个业务模块的命令必须明确实际影响，不能悄悄覆盖其他模块。

## 面板与中央系统

- 中央控制器仍使用 Shift＋右键打开管理界面。
- 新方块：**舱内信息面板**，ID `dbv_world:cabin_panel`。普通右键打开同一界面，不替代主艇资格所需的 Deep Seas 中央控制器。
- 可在创造模式“功能方块”分类获取，或执行 `/give @s dbv_world:cabin_panel`。合成：外围7个铁锭，上中玻璃板，正中红石。
- 面板必须在已登记主艇上，或当前船坞改装范围内。装在岸上不会自动绑定最近的潜艇。
- 页面：船况与改装、艇内设备、舱内存储。船况显示永久 ID、载体代次、质量和速度；存储按容器和槽位显示物品名称及数量。
- 信息每秒刷新；常规扫描只检查主艇范围，不扫描全世界、不预加载远海。UI最多128行并明确提示截断，独立快照不按UI截断。
- 外观是首版完整方块终端，使用原版贴图；暂未提供薄型墙面屏幕。
- 新生成的初始艇自带箱子、木桶和信息面板。已有地图不自动改写船体，可开始改装后放置这些方块。

## 备份与恢复

“备份存储”先扫描真实容器并更新 JSON，再生成独立快照。“恢复最近备份”需要二次点击确认，仅在船坞中、改装结束后，由建设模式创造管理员使用。查看存储不要求管理员权限。

恢复前先核对所有容器的相对位置、方块类型、槽位数量和写入能力；先完整解码所有物品，再生成恢复前快照和恢复事务标记，然后修改实际槽位并逐槽核对。世界成功保存后才清除标记。发生异常尝试还原操作前内容；若还原或保存失败，保留标记与快照。进程中途退出会保留标记，停止后续独立档案更新与恢复，避免不确定的内容覆盖备份；目前需人工核对，**不是任意崩溃自动恢复**。

改装开始时也会生成业务 JSON 快照，并在现有改装事务中记录其 ID。取消或失败还原时恢复该业务快照，再从恢复后的真实船体更新存储与载体记录。正常物理状态每5秒扫描结构与容器，正常退出前再同步一次。船体结构、物品或其他业务模块变化时生成自动快照，保留最近20份；手动和改装前快照不受此清理影响。结构、容器、载体资料在同一服务器线程同一次扫描中采集，通过一次原子写入发布，随后归档该版本，避免结构与物品属于不同版本。

普通物理建造新增/拆除的方块和槽位内容也参与同步，不要求进入方块改装。结构快照采用方块状态 Codec JSON；第三方方块实体通过 Minecraft 原有保存接口读取后，转换成带类型的 JSON 字段，保留数值类型、长整数精度、数组和嵌套内容，不产生新的 `.nbt` 文件。它是第三方元数据边界适配器，不是把业务数据放回面板 NBT。动态设备的完整元数据会随当前档案更新，但仅能量计数/氧气变化不会每5秒创建历史快照，避免无限历史增长。UI仍每秒刷新。

支持原版 `Container`，以及提供无方向 `ItemHandler` 能力的 Mod 设备；只读处理器可以查看和备份，但整批恢复会拒绝它们，避免部分恢复。仅有侧面接口、外部网络、跨船连接、流体和能量不属于当前物品恢复范围。恢复操作覆盖容器内容，不追回玩家拿走或丢在世界里的物品，因此暂不开放生存模式。

## 与世界存档的边界

独立 JSON 已记录结构、设备元数据和物品，但当前界面的“恢复最近备份”仍是**存储恢复，不会重建船壳**；自动结构快照的整船重建入口尚未实现。Minecraft/Sable仍使用各自世界存档；既有 `dock/block-refit.nbt`、样艇系泊记录和旧版改装历史仍用于物理改装还原，未删除或转换。当前不宣称已经消除所有上游 NBT。

只备份业务数据可复制整个 `vessels/<vesselId>` 目录；完整灾难恢复仍需关闭世界后备份整个世界目录。不要只恢复 `state.json` 就假设实际容器已经变化，应通过恢复流程应用快照。后续需接入整船重建、实体引用版本和旧档迁移测试，再替换既有物理备份。

证据位于 `outputs/cabin-storage-20261014/`：`acceptance.log`、`restart.log`、`storage.png`、`vessel.png`、`sample-state.json`。早期失败记录保留：脚本的 Rhino 方法转换/文件类访问限制，以及一次 Create 注册回调启动失败；最终两次运行均正常退出。正式世界未修改，验收世界已移到 `runtime/backups/DBV-Cabin-Storage-Acceptance`，临时运行脚本已清理。
