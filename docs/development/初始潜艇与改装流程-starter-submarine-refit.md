# 初始潜艇与改装流程

更新：2026-10-14。Minecraft 1.21.1 / NeoForge 21.1.259 / Sable 2.0.6 / Deep Seas 3.3.0。此轮将原来的“在物理船上编辑”改为“物理船体 → 世界方块 → 验收后重新装配”。功能尚限建设阶段，不是完整生存潜艇成品。

## 正确的改装流程

1. 靠近船坞中的唯一主艇，Shift＋右键船载电脑打开中文面板。控制器已损坏或已被拆下时，使用 `/dbv refit` 打开同一界面。
2. 点击 **开始改装**。开始不检查控制器、供氧或密闭资格；缺氧、开着舱门或破舱都可以进入改装。仍需真实主艇已加载、身份无冲突、创造管理员权限、建设模式、船坞系泊和足够的空泊位。
3. 先保存原船方块状态及方块实体 NBT 数据，再将船体移到船坞世界坐标，移除原物理载体。此时真的成为可编辑的普通世界方块，不是仅冻结物理船。设备数据未加载或无法反序列化时停止操作并提示位置。
4. 关闭窗口施工。可放置原版与 Mod 方块，也可拆除控制器，入口消失时用 `/dbv refit` 重新打开。世界方块阶段的氧气和密闭显示“完成时检测”，不虚报运行状态。
5. 点击 **完成改装**。内部先临时装配并固定候选船体，等待 Deep Seas 的真实舱室与供氧扫描（最多20秒）；只有中央控制器、制氧供氧系统、密闭空间都通过才交付物理船体。临时装配是为了调用上游检测，不代表已通过验收；期间禁止编辑和重复提交。
6. 验收失败或主动取消：恢复改装前备份并还原为物理船体。原本缺氧或破舱的船会恢复到原来的状态，不要求备份本身符合三条件。

三项条件属于“首次登记／完成改装”的资格门槛，**不是开始改装的门槛**。此次重新装配会改变 Sable 的物理载体 UUID，自研永久 `vesselId`、名称与世界归属不变，载体代次递增。它仍是同一艘主潜艇，不占用第二个主艇名额。

## 初始小艇与泊位

本机地图为 `runtime/client/saves/DBV-Island-v2`，游戏名称 **Deep Blue Voyage - Starter Submarine v2**；也可新建“深蓝远航 起始岛”预设。旧世界不会因更新被自动重建。

初始小艇约9×7×15，位于 `(60,68,150)` 至 `(68,74,164)`，包括船壳、玻璃、顶部舱口、船载电脑、电解器、氧气扩散器及红石供电。建设模式的船坞岸供为物理样艇补充水、FE和氧气。没有推进、武器或酒狐 AI。

方块改装使用以 `(60,68,150)` 为原点的泊位。先检查原船体占用空间为空，且没有其他物理船占用，才允许拆解。完成时以原包围盒内方块为种子，按六个面邻接向外扫描，原范围外连接的船壳和容器也会装配。独立放在旁边的物体不纳入；仅对角接触不算连接；自由水/岩浆不参与扫描，含水实体方块仍参与。改装保护与扩建范围是原包围盒向各侧扩16格，再裁剪到船坞边界（X 0～127、Y 65～100、Z 112～239）；装配后的总包围盒仍限4096格。超限或连接到范围外岸边结构时拒绝转换，请先断开连接。

选中的外接方块坐标在转换前落盘；取消、验收失败还原时清理这些坐标并恢复原船，附近未连接的物体不受影响。已拆成独立物体的外部零件不属于连接船体。普通物理状态下已允许原版/Sable正常放置和拆除方块，不必先开始改装；仅活动改装的转换、验收、恢复阶段锁定物理船体编辑。普通编辑没有自动撤销按钮，使用独立结构与存储快照保留记录。

## 出航测试

“船况与改装”页底部新增 **出航**，目前限建设模式创造管理员，需靠近船坞内已系泊主艇、且没有活动改装。点击立即解除固定约束并断开岸供（水、FE、氧气）；不会传送或自动驾驶。初始小艇并未自带完整推进系统，出航用于测试自由物理行为，可能下落或下沉。

出航状态保存在主艇 JSON 的 `modules.navigation.departed`，后台和重启后不会自动重新系泊。已出航时按钮显示“已出航”并禁用。返航、重新系泊按钮尚未实现；请先用测试地图进行出航测试。离开船体过远时管理界面会断开，登艇后通过控制器/面板重新打开。

新版方块改装已取消材料白名单：原版及 Mod 方块默认允许放置，包括楼梯、台阶、门、装饰、红石、箱子、木桶和 Create 设备。备份包含方块状态与方块实体 NBT（包括保存在其中的物品、流体、能量及配置），装配与拆解使用 Sable 的移动接口。恢复时先放全方块再恢复设备数据，避免门、床或附着方块因支撑尚未恢复而提前破坏。设备列表不会再将所有未知设备误标成“供氧”。

允许放置不代表所有 Mod 都已验证物理兼容。跨船/世界连接、线缆网络、外部坐标引用、运动机械、嵌套子船、非玩家实体，以及不保存在方块实体 NBT 中的状态，仍不保证完整恢复。施工中的物品转移和掉落物不属于整船回滚范围；当前仍限定创造建设阶段。旧版活动改装事务保留旧恢复逻辑与限制，结束后新开的事务采用上述规则。其他开发者不能接管当前事务。管理员命令、WorldEdit、外部脚本等绕过普通方块事件的操作不属于编辑保护保证范围。

## 持久化与中断处理

文件位于存档 `dbv/fleet/`：

| 文件 | 作用 |
| --- | --- |
| `registry.json` | 永久主艇身份、当前物理载体 UUID 与代次 |
| `dock/starter.nbt` | 当前样艇载体及系泊点 |
| `dock/block-refit.nbt` | 新流程活动事务：原始备份、原载体、候选载体、所有者、世界方块范围及转换阶段 |
| `dock/history/*-blocks-*.nbt` | 已完成、取消、验收拒绝或重启还原的记录 |
| `dock/active-refit.nbt` | 旧版物理船内编辑事务，仅用于兼容恢复；新事务不再创建此文件 |

原始快照在拆解前落盘；阶段写入通过临时文件、强制落盘和原子替换进行。正常方块改装阶段退出，下次启动自动恢复原始船体。若在拆解、装配、载体登记或还原等转换阶段意外中断，当前版本锁定并保留现场，**不自动猜测或再生成一艘船**，需要核对档案后处理。此边界不同于完整的任意时刻灾难重建，目前尚未实现后者。

旧版活动事务仍由兼容实现还原，避免升级后丢失先前备份。不要手工删除活动记录或 pending 文件来解锁。
