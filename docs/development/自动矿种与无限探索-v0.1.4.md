# 自动矿种与无限探索（v0.1.4）

## 用户确认

- 在世界生成之前扫描物品，加入明确在主世界自然生成、可挖掘的矿石和宝石，不加入绯红岩等需要加工提矿的岩石。
- 原有自然矿物生成保留。
- 距离初始岛最近的三座资源岛依次保障铁、铜、金，其他岛屿随机。
- 10000 格正方形以外沿用相同生成规则，使用同一世界种子，随探索生成，不全图预生成。
- 现有存档可以删除重建。本次保留压缩回退备份，替换活动存档。

## 扫描和存档稳定性

在 NeoForge 完成群系修饰器处理之后、加载世界区块之前执行一次扫描。遍历物品注册表，从方块物品中筛选：

1. 有矿石标签；且目标方块出现在当前主世界生成器实际可用群系的矿脉配置中；且能解析出挖掘掉落。
2. 或者出现在主世界晶洞的晶簇放置列表中，并有宝石标签物品的掉落证据。未成熟、只掉自身的晶芽不纳入。

普通与深层矿石按通用矿种标签合并为一个矿种，优先普通矿石；铁、铜、金、锌可混入对应粗矿块。紫水晶生成带实体支撑的成熟晶簇和水下晶体空腔，不用紫水晶装饰块代替可采集宝石。

当前支持标准矿脉、散布矿脉和晶洞的可解析生成数据；没有标签、没有主世界挂载证据、只由模组私有代码生成或没有可解析掉落的候选不猜测加入。扫描报告保留候选排除原因；增加这类模组时需要针对其生成器补充识别。这不是靠物品名称包含“矿”就全部纳入。

当前安装组合识别出 **10 种**：煤、铁、铜、金、红石、青金石、钻石、绿宝石、锌、紫水晶。石英和远古残骸没有主世界生成证据；绯红岩、辉绿岩、赭金砂、皓蓝石不满足矿石筛选。

存档内 `dbv/worldgen-minerals.json` 固定矿种及代表方块，`dbv/mineral-scan-report.json` 保存每次启动的扫描证据。已有快照不会因增加模组而重新排列岛屿矿种；新地图使用最新扫描结果。已有地图如需扩充矿池，应另做明确迁移。缺失快照引用的方块会中止启动并提示恢复模组，避免静默变矿。

## 地图布局

中心 [-5000,5000) 正方形仍有 3 个主线占位区域、24 座资源岛。最近三岛按岛中心到初始岛中心 (0,0) 的水平直线距离排序，分别为铁、铜、金；其余以世界种子和位置确定随机矿种，可重复，不保证每个分区出现全部矿种。

外部按 10000×10000 格分区，以世界种子和分区坐标确定局部布局。每个分区沿用 3 个区域占位、24 座资源岛的开发密度；外部区域没有主线任务。区边预留至少 400 格，避免相邻分区岛屿重叠。分区只是计算布局，不预生成区块，不同探索顺序不会改变地点和矿种。每分区数量和间距是本版实现参数，后续仍可调整。

世界边界恢复原版通常使用的 59,999,968 格直径。海面 128、最低 -256、起始岛和船坞保护保持。

原版与模组自然矿物的配置、配方和掉落表不修改。移除旧版针对资源岛的跨区块自然装饰拦截和其他矿石清除；额外矿脉只替换普通石头/深板岩或新增岛体，不抹掉原有矿石、洞穴与建筑。每岛只有一种**额外分配资源**，原地形中的其他天然矿物可以共存。
